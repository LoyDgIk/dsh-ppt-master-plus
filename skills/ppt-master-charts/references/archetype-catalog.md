# Archetype catalog — structure, process, comparison

Forms for pages whose content is **not** a quantitative series. Upstream
catalogues 33 charts by encoded relationship; it declares qualitative structure
out of scope. These are the forms that fill that space.

Each entry gives the **information relationship** the form encodes — not a
drawing recipe (upstream owns construction) and not a look (styles live in
[`style-profiles.md`](./style-profiles.md)).

Every entry is style-independent by construction. If a form only reads well in
one palette, it is a style, and it does not belong in this table.

**How to read the columns**

- **Answers** — the question the audience has, which this form resolves.
- **Data shape** — what content the form structurally requires. If you cannot
  fill this, the form is wrong for the page.
- **Avoid when** — the specific, common misuse.

## 1. Structure — "what is it made of, and how do the parts relate?"

| key | 名称 | Answers | Data shape | Avoid when |
| --- | --- | --- | --- | --- |
| `radial_hub` | 同心辐射 | What binds these parts together? | 1 core + 4–10 spokes, each with a name and one fact | The parts are not actually coordinated by the centre |
| `platform_stack` | 分层架构 | How do layers support each other? | 3–6 ordered layers, each with a role | Layers are peers; that is a honeycomb, not a stack |
| `honeycomb` | 蜂窝结构 | Which peer capabilities exist? | 4–12 equal cells, each with a name and a metric | The cells differ in weight — unequal cells must look unequal |
| `pyramid` | 金字塔 | What is the hierarchy of support or volume? | 3–6 ordered tiers, widest at the base | Quantities do not actually narrow; then it is a list |
| `inverted_pyramid` | 倒金字塔 | What narrows toward the bottom? | 3–5 tiers, narrowest at the base | Used to imply "fewer is better" without saying so |
| `onion_layers` | 洋葱层 | What must you pass through to reach the core? | 3–5 nested layers + a core | The layers are sequential in time — that is a funnel |
| `iceberg` | 冰山 | What is visible versus what is hidden? | Two blocks: visible surface, larger submerged mass | Only one side has content; it becomes a decorative metaphor |
| `umbrella` | 伞形 | What does one policy or platform cover? | 1 cover + 3–8 beneficiaries underneath | The cover is not genuinely shared |
| `jigsaw` | 拼图 | Which parts must fit together to complete it? | 3–8 interlocking pieces, one clearly missing or highlighted | Pieces are independent; independence is not jigsaw |
| `org_tree` | 组织架构树 | Who reports to whom? | Directed parent→child edges, 2–4 levels | Edges are not authority, they are flows |
| `network_topology` | 协同网络 | Who connects to whom, and through what? | Nodes + edges, with an identifiable hub or cluster | Any two nodes connect equally — then it is a grid |
| `ecosystem_rings` | 生态圈层 | Who is closest to the core, and who is peripheral? | 3–4 concentric rings + a core | Membership is binary; rings imply a gradient |
| `value_chain` | 价值链 | Where is value added along the chain? | Ordered primary activities + supporting activities that span them | Activities are not sequential |
| `house_model` | 房屋模型 | What is the roof, the pillars, the foundation? | 1 goal + 2–4 pillars + 1 foundation | Any part has no content; an empty pillar is conspicuous |
| `pillar_columns` | 支柱模型 | What holds the goal up? | 1 top goal + 2–5 supporting pillars | Pillars are sequential steps |
| `three_legged_stool` | 三脚凳 | What three things are jointly necessary? | Exactly 3 necessary, non-substitutable supports | There are four; use pillars |
| `flywheel` | 飞轮 | What reinforces itself? | 4–8 stages forming a closed, causal loop | The loop has no real causal return edge |
| `orbit` | 轨道模型 | What orbits a centre at different distances? | 1 centre + 2 rings of 3–8 items | Proximity carries no meaning |
| `gears` | 齿轮联动 | What turns what? | 2–5 interlocking mechanisms with a direction | The parts do not actually drive each other |
| `bridge` | 桥梁模型 | What connects two separated sides? | 2 banks + a connecting span with supports | There is only one side |
| `petal_model` | 花瓣模型 | What unfolds from one core capability? | 1 core + 5–8 petals of equal weight | The petals overlap; overlap is a Venn |
| `spiral` | 螺旋递进 | How does the same activity deepen over rounds? | 3–5 turns, each with a higher-level outcome | The rounds are unrelated activities |
| `mosaic` | 马赛克拼合 | How do many small parts make one whole? | 6–20 tiles + a stated whole | Tiles do not compose into the stated whole |
| `modular_blocks` | 模块化积木 | What can be recombined? | 5–12 labelled modules + 2–3 composition examples | Modules are fixed in one configuration |
| `tree_decomposition` | 树状分解 | How does one thing break into sub-things? | A root plus 2–3 levels of decomposition | Depth exceeds three levels; detail belongs elsewhere |
| `spectrum` | 谱系定位 | Where do things sit on one continuous range? | 1 named axis + 2–6 positioned items | The axis is actually two independent dimensions |
| `staircase` | 阶梯递进 | What must be achieved in order to reach the top? | 3–6 ordered levels, each a precondition | Levels can be skipped |
| `satellite_constellation` | 卫星群 | Which small units serve one mission? | 1 mission + 4–10 units at varied distance | Units are peers; use honeycomb |
| `moat` | 护城河 | What protects this position, in what order? | A core + 2–4 defensive layers | The layers are not defensive |
| `lens` | 透镜视角 | How does one body of content look through several lenses? | 1 subject × 3–4 lenses | Lenses are just sections |
| `nine_box` | 九宫格 | What exists at each of 3×3 positions? | Exactly 9 cells, rows and columns both named | Either axis is unnamed; then it is a plain grid |
| `totem` | 图腾柱 | What is the priority order from top to bottom? | 4–7 stacked priorities | The order is not a priority |
| `venn` | 维恩交汇 | What exists only where these sets overlap? | 2–3 sets + explicitly named intersections | The interesting part is not the intersection |
| `moat_layers` | 纵深防御 | (alias of `moat`) | — | — |

## 2. Process — "what happens first, and where is it stuck?"

| key | 名称 | Answers | Data shape | Avoid when |
| --- | --- | --- | --- | --- |
| `arrow_chain` | 箭头链 | What is the sequence? | 3–7 ordered steps | The steps loop — use a closed loop |
| `closed_loop` | 闭环 | How does the process return to its start? | 3–6 steps + a genuine return edge | There is no real return; a fake loop misleads |
| `chevron_process` | 人字箭头流程 | What is the sequence, with emphasis on direction? | 3–6 steps, left to right | More than 7 steps; switch to a numbered list |
| `serpentine` | 蛇形流程 | How does a long sequence wrap into a compact space? | 6–14 steps over 2–3 rows | Fewer than 6 steps |
| `funnel` | 漏斗 | Where do we lose volume through a conversion? | 3–6 **monotonically non-increasing** stage values | Stages can increase; a funnel implies loss |
| `dual_funnel` | 双漏斗 | How do two funnels meet? | 2 funnels sharing a middle constraint | The funnels are unrelated |
| `hourglass` | 沙漏 | Where is the bottleneck between two halves? | Inbound stages, one constraint, outbound stages | No single constraint is identified |
| `timeline_h` | 横向时间轴 | What happened, in order, along time? | 4–8 dated or ordered events | Dates do not matter, only order — use a chain |
| `timeline_v` | 纵向时间轴 | Same, read top to bottom | 4–8 events | The page has horizontal room and few events |
| `dual_track_timeline` | 双轨时间轴 | How do two streams proceed in parallel? | 2 tracks × 3–6 events on a shared axis | The tracks do not share an axis |
| `swimlane` | 泳道 | Who does what, at which stage? | 3–6 lanes (owners) × 3–8 stages | Ownership is uniform; lanes add nothing |
| `decision_tree` | 决策树 | Which path do we take, given what? | Branch nodes with explicit conditions | Branches have no stated condition |
| `kanban` | 看板 | What is the state of work in progress? | Columns (states) + items with counts | Work has no states |
| `stage_gate` | 阶段门 | What must be true to proceed? | Stages separated by explicit entry criteria | Gates have no criteria |
| `roadmap` | 路线图 | What is planned, when, and toward what? | Time buckets × workstreams + milestones | Horizons are unknown; that is a backlog |
| `metro_map` | 地铁图 | How do several lines share stations? | 2–4 lines crossing at named shared nodes | Lines do not intersect |
| `milestone_track` | 里程碑轨 | Which few points mark real progress? | 4–7 milestones with dates and deliverables | Every task is shown; that is a Gantt |
| `lifecycle` | 生命周期 | How does this mature, and what comes after? | 4–6 ordered phases → renewal or decline | Phases are arbitrary |
| `pdca` | PDCA 循环 | How does a plan–do–check–act cycle run? | Exactly 4 stages, closed | There are 5+ stages; use a generic loop |
| `value_stream` | 价值流 | Where does time go, and where is waste? | Ordered stages with cycle time and wait time | Times are not measured or estimated |
| `waterfall_phases` | 瀑布阶段 | What is delivered at the end of each phase? | Sequential phases, each with a deliverable | Phases overlap heavily |
| `spiral_model` | 螺旋模型 | How does risk drive repeated rounds? | Rounds, each with analysis→build→evaluate | There is no risk-driven repetition |
| `five_whys` | 五问法 | What is the root cause under the symptom? | A chain of 3–6 "why" levels, narrowing to one cause | The chain stops at a person rather than a cause |
| `sipoc` | SIPOC | Who supplies, what goes in, what comes out, to whom? | 5 named columns, filled | The process has no clear boundary |
| `escalation_ladder` | 升级阶梯 | Who handles what, and when does it escalate? | Ordered severity levels + owners + timeframes | Escalation never triggers |
| `fork_merge` | 分叉合流 | Where do paths diverge and rejoin? | 1 split, N parallel branches, 1 merge | Branches never rejoin |
| `branching_path` | 分支路径 | Which of several routes applies to whom? | 1 entry + 2–4 conditional routes | Conditions are unstated |
| `relay_baton` | 接力交接 | Where does responsibility move? | Ordered owners, each handing off a deliverable | A single owner does everything |
| `handoff_chain` | 交接链 | What breaks at each hand-off? | Ordered hand-offs + the risk at each | There are no hand-offs |
| `convergence` | 汇聚 | How do many inputs become one outcome? | 3–8 inputs → 1 result | The inputs are sequential |
| `countdown` | 倒计时 | How much time remains, and what must happen? | Remaining periods + required actions | The deadline is not fixed |
| `state_machine` | 状态机 | What states exist, and what moves between them? | States + labelled transitions | Only one path exists |
| `cpr_steps` | 急救步骤 | What must be done, in strict order, under pressure? | 3–6 ordered imperative steps | Order is optional |
| `improvement_cycle` | 改进循环 | Where does the loop tighten each round? | A loop + a metric that improves per round | No metric improves |
| `numbered_steps` | 编号步骤 | What are the steps, plainly? | 3–8 numbered items | The steps have no real order |

## 3. Comparison — "which is better, by how much, and how do we choose?"

| key | 名称 | Answers | Data shape | Avoid when |
| --- | --- | --- | --- | --- |
| `side_by_side` | 左右对照 | How do these two differ? | 2 columns × 3–6 shared dimensions | The two are not comparable on shared dimensions |
| `before_after` | 前后对比 | What changed? | Same metrics, two states, with deltas | Only one state has data |
| `current_vs_target` | 现状与目标 | How far are we from the goal? | Per dimension: current, target, gap | Targets are unstated |
| `swot` | SWOT | What helps, what hurts, internally and externally? | 4 quadrants, 3–5 items each, internal/external separated | Items are miscategorised; S/W are internal, O/T external |
| `option_cards` | 方案卡 | Which option should we pick? | 2–4 options × same dimensions + a stated recommendation | No recommendation is given |
| `scoring_matrix` | 评分矩阵 | How do options score on weighted criteria? | Options × criteria + weights + scores | Weights are missing; unweighted scoring is a tally |
| `weighted_scorecard` | 加权评分卡 | (alias of `scoring_matrix`, totals shown) | — | — |
| `ranked_options` | 排序选项 | What is the order? | Ordered items + the ranking criterion | The criterion is unstated |
| `pros_cons` | 优劣势 | What argues for and against? | Two balanced lists + a verdict | One side has three times the items; that is a decision already made |
| `feature_table` | 功能对比表 | Which option has which capability? | Options × features, present/absent/partial | Rows outnumber the audience's attention; cut rows |
| `quadrant_2x2` | 四象限 | How do items position on two dimensions? | 2 named axes + positioned items | Either axis is unnamed |
| `positioning_map` | 定位图 | Where does each player sit in the market? | 2 axes + labelled points | Positions are asserted without basis |
| `bcg_matrix` | BCG 矩阵 | Which businesses to invest in or exit? | Growth × share + 4 named strategies | Share or growth is unknown |
| `risk_matrix` | 风险矩阵 | Which risks need attention first? | Likelihood × impact + mitigation per risk | No mitigation is stated |
| `gap_analysis` | 差距分析 | Where is the shortfall? | Per dimension: expected, actual, gap | The cause of the gap is not named |
| `maturity_model` | 成熟度模型 | How mature are we, per dimension? | 4–6 levels × dimensions + current level marked | Levels are not defined behaviourally |
| `harvey_balls` | 哈维球 | How strong is each of several capabilities? | 3–8 capabilities, filled vs empty balls | Only one capability matters |
| `strategy_canvas` | 战略画布 | Where do we differ from competitors on factors? | Competing factors × value curves for 2–4 players | Factors are not decision-relevant |
| `price_value_map` | 价格-价值地图 | Where is the value-for-money frontier? | Price × perceived value + positions | Value is unmeasured and unargued |
| `pricing_tiers` | 价格方案 | Which tier fits which buyer? | 2–4 tiers × included features + price | Tiers differ only by price |
| `tco_comparison` | TCO 对比 | What is the true total cost? | Cost categories × options, summed over a horizon | Only acquisition cost is counted |
| `balance_scale` | 天平权衡 | What is being traded against what? | Two weighted sides + a tipping judgement | The sides are not comparable |
| `trade_off_curve` | 权衡曲线 | What does more of one cost in the other? | A frontier with positions on it | No real trade-off exists |
| `ab_test` | A/B 测试 | Which variant won, and by how much? | Two variants + a metric + significance | Sample or significance is unknown |
| `cost_benefit` | 成本收益 | Does the benefit justify the cost? | Cost and benefit streams + net position | Benefits are not quantified or labelled as estimates |
| `red_team` | 红蓝对抗 | What is the strongest counter-argument? | A position + its strongest objections + responses | Objections are strawmen |
| `build_buy_partner` | 自建/采购/合作 | Which sourcing route? | 3 routes × shared criteria + a recommendation | No recommendation |
| `start_stop_continue` | 开始/停止/继续 | What should change next period? | 3 buckets with concrete items | Items are vague intentions |
| `do_nothing` | 不行动方案 | What happens if we do nothing? | The status quo as an explicit option with consequences | It is used to frighten rather than compare |
| `dimension_radar` | 维度雷达 | How do several entities profile across dimensions? | 3–8 dimensions × 2–4 entities, same scale | Dimensions exceed 8; the shape becomes unreadable |

**Note on `dimension_radar` and other quantitative forms.** A radar, a Gantt, a
funnel with measured values and a pareto all exist upstream as `chart/<key>`
references. This table lists them only where the *page's intent* is comparison
or process; when the page is fundamentally a value encoding, use upstream's
reference and its value-driven authoring contract. See
[`data-archetypes.md`](./data-archetypes.md).

## Using the catalog

1. Decide the intent (§1/§2/§3 here, or §D/§E in `data-archetypes.md`).
2. Pick 2–3 candidate keys whose **Answers** column matches your one sentence.
3. Read their **Data shape** columns. Discard any candidate whose shape your
   content cannot fill — this is where most bad chart choices die.
4. Read **Avoid when**. If it applies, go back to step 2.
5. Record the key in `chart_plan.json` and let `chart_plan.py` re-check the shape
   mechanically.

A catalog entry is a hypothesis, not a mandate. Zero entries from this table is
a valid outcome for a narrative page.

## Extending the catalog

Adding a form is welcome. Requirements, in order:

1. It encodes an **information relationship** that none of the existing keys
   encodes. A new *look* for an existing relationship is a style profile.
2. It is style-independent: describable without naming a colour, font or brand.
3. It has a **Data shape** column that can be checked mechanically, or an
   explicit statement of why it cannot.
4. It has an **Avoid when** column naming a real, common misuse.

Then add its data-shape rule to `scripts/chart_plan.py` so the check keeps up
with the catalog. A catalog entry with no rule is a suggestion; an entry with a
rule is a contract.
